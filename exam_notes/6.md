## CORE DEFINITIONS

### What is a Markov Decision Process (MDP)?
A sequential decision problem for a fully observable, stochastic environment with Markovian transitions and additive rewards, defined by the tuple \((S, A, T, R)\):
- \(S\): set of states
- \(A\): set of actions
- \(T(s, a, s')\): stochastic transition function \(P(s'|s,a)\)
- \(R(s)\): reward function

**Key points:**
- Markovian property: future depends only on current state, not history
- Foundation for both planning (when model known) and RL (when model unknown)
- Fully observable: agent knows its current state[1]

### What is a policy?
A policy \(\pi: S \to A\) is a function that specifies what action the agent should take in any given state.

**Key distinctions:**
- **Fixed/deterministic policy:** \(\pi(s) = a\)
- **Stochastic policy:** \(\pi(a|s)\) gives probability distribution over actions
- **Quality measure:** Policy quality is expressed via value functions[1]

***

## VALUE FUNCTIONS & BELLMAN EQUATIONS

### State value function \(V^\pi(s)\)
Expected total payoff (reward-to-go) when starting in state \(s\) and following policy \(\pi\).

**Bellman equation for policy evaluation:**
\[V^\pi(s) = R(s) + \gamma \sum_{s'} T(s, \pi(s), s') V^\pi(s')\]

- **Immediate reward:** \(R(s)\)
- **Future reward:** Discounted expected value of successor states
- **Discount factor \(\gamma\):** (0 < \(\gamma\) ≤ 1) balances immediate vs future rewards
- Forms a system of linear equations (no max operator)[1]

### Optimal value function \(V^*(s)\)
\[V^*(s) = R(s) + \gamma \max_a \sum_{s'} T(s, a, s') V^*(s')\]

The maximum expected value achievable from state \(s\).

### Optimal policy \(\pi^*\)
\[\pi^*(s) = \arg\max_a \sum_{s'} T(s, a, s') V^*(s')\]

Selects the action that leads to highest expected value.[1]

### Action-value function \(Q(s,a)\)
Utility of performing action \(a\) in state \(s\), then following a policy.

**Q-value Bellman equation:**
\[Q^*(s,a) = R(s) + \gamma \sum_{s'} T(s, a, s') \max_{a'} Q^*(s',a')\]

**Key advantage:** With \(Q^*(s,a)\) learned, optimal action is simply \(\arg\max_a Q^*(s,a)\)—no model needed for action selection.[1]

## PLANNING vs REINFORCEMENT LEARNING

### Planning (model-based)
**Assumptions:**
- Transition model \(T\) is known
- Reward model \(R\) is known

**Methods:**
1. **Value iteration:** Repeatedly apply Bellman equation updates until \(V\) converges, then derive \(\pi^* = \arg\max_a\)
2. **Policy iteration:** Alternate between (1) policy evaluation (solve linear system for \(V^\pi\)) and (2) policy improvement (greedy update)

**Good for:** Small state spaces where model is available[1]

### Reinforcement Learning (model-free or model-based learning)
**Used when:** \(T\) and/or \(R\) are unknown and must be learned from interaction

**Core challenge:** Agent must learn good behavior through trial and error, balancing exploration (gathering information) and exploitation (using current knowledge)[1]

## PASSIVE REINFORCEMENT LEARNING

### Definition
In passive RL, the agent's policy \(\pi\) is **fixed**; the task is to learn "how good" that policy is by estimating \(V^\pi(s)\).[1]

### Method 1: Direct Utility Estimation
**Approach:**
- Run many trials from start state to terminal state
- Each trial gives sample of reward-to-go for visited states
- Maintain running average per state

**Pros:** Simple, unbiased
**Cons:** High variance, slow convergence, ignores Bellman structure—treats states independently[1]

### Method 2: Adaptive Dynamic Programming (ADP)
**Approach:**
- Learn approximate transition model \(P(s'|s)\) from observed transitions
- Plug learned transitions and observed rewards into Bellman equations
- Solve for \(V(s)\) for the fixed policy (linear system)

**Pros:** Uses Bellman dependencies to speed up estimation
**Cons:** Requires building and storing a model; computationally expensive for large state spaces[1]

**Why linear system?** No max operator in policy evaluation—policy is fixed, so \(V^\pi(s) = R(s) + \gamma \sum_{s'} P(s'|s,\pi(s)) V^\pi(s')\) [1]

### Method 3: Temporal Difference (TD) Learning
**Approach:**
- Model-free: does not build transition model
- Updates state value using observed transitions
- **TD update rule:**
\[V(s) \leftarrow V(s) + \alpha [R(s) + \gamma V(s') - V(s)]\]

where \(\alpha\) is learning rate, \(s'\) is observed next state

**Key idea:** Bootstrapping—update current estimate using next state's current estimate, not waiting for final return[1]

**ADP vs TD:**
- ADP adjusts utility of \(s\) using **all successor states** via learned model
- TD adjusts using **one sampled successor** \(s'\) from experience[1]

**Pros:** Model-free, online learning, often faster early convergence than direct estimation
**Cons:** Biased early (bootstrapping from imperfect estimates), requires tuning learning rate

## ACTIVE REINFORCEMENT LEARNING

### Definition
In active RL, the agent must **choose actions while learning**—the policy is not fixed. The agent faces the exploration vs exploitation dilemma.[1]

### Exploration vs Exploitation Trade-off
- **Exploitation:** Choose actions that look best under current learned model/policy (maximize immediate expected reward)
- **Exploration:** Choose actions to gather information and improve the model/policy, possibly sacrificing short-term reward

**Risk:** Pure exploitation may lock agent into suboptimal behavior based on faulty early learning; agent fails to discover better options[1]

**Common exploration strategies:**
- **ε-greedy:** With probability ε, choose random action; otherwise choose greedy action
- **Optimistic initialization:** Start with high initial Q-values to encourage exploration
- **UCB (Upper Confidence Bound):** Balance exploration and exploitation using uncertainty estimates

### Method 1: Q-Learning
**Approach:**
- Learn action-values \(Q(s,a)\) directly from experience
- **Update rule:**
\[Q(s,a) \leftarrow Q(s,a) + \alpha [R(s) + \gamma \max_{a'} Q(s',a') - Q(s,a)]\]

**Key characteristics:**
- **Off-policy:** Updates toward greedy action (\(\max_{a'} Q(s',a')\)) even if a different action was actually taken
- Converges to \(Q^*\) under appropriate conditions (visit all state-action pairs infinitely often, learning rate decay)
- Does not require a model[1]

**Derived policy:** \(\pi(s) = \arg\max_a Q(s,a)\)

### Method 2: SARSA (State-Action-Reward-State-Action)
**Approach:**
- Also learns \(Q(s,a)\)
- **Update rule:**
\[Q(s,a) \leftarrow Q(s,a) + \alpha [R(s) + \gamma Q(s',a') - Q(s,a)]\]

where \(a'\) is the action **actually chosen** in \(s'\) under current behavior policy

**Key characteristics:**
- **On-policy:** Updates based on action actually taken by current policy (including exploration)
- Learns value of the policy being executed (including exploration randomness)
- Typically learns safer policies in risky environments when using ε-greedy[1]

### Q-Learning vs SARSA (exam-critical contrast)
| Aspect | Q-Learning | SARSA |
|--------|-----------|-------|
| **Update target** | Greedy action (\(\max_{a'} Q(s',a')\)) | Actual next action \(a'\) taken |
| **Policy type** | Off-policy | On-policy |
| **Risk behavior** | Optimistic (assumes greedy future) | Conservative (reflects exploration risk) |
| **Use case** | When you want optimal policy regardless of exploration | When safety during learning matters |

**Example:** Near a cliff with ε-greedy exploration, Q-learning updates assume greedy safe action, but ε-exploration may cause falls; SARSA updates reflect actual exploration risk, learning to stay farther from cliff.[1]

## COMPLETE EXAM QUESTIONS & ANSWERS

### Q1: What is an MDP and why does it matter for RL?
**Answer:**
An MDP is a sequential decision problem defined by states \(S\), actions \(A\), a stochastic transition function \(T(s,a,s')\), and a reward function \(R(s)\), modeling decisions under uncertainty with the Markov property (future depends only on current state). It matters for RL because many RL methods are essentially ways to learn good policies or value functions in an MDP when the model \(T\) and/or \(R\) is unknown. The MDP framework provides the mathematical foundation for both planning and learning.[1]

***

### Q2: What is a policy and how do you measure its quality?
**Answer:**
A policy \(\pi\) is a function mapping each state to an action, i.e., \(\pi: S \to A\). Its quality is measured via the value function \(V^\pi(s)\), which is the expected cumulative reward (reward-to-go) when starting in state \(s\) and following policy \(\pi\). Higher \(V^\pi(s)\) means better expected performance. The optimal policy \(\pi^*\) achieves the maximum value \(V^*(s)\) in every state.[1]

***

### Q3: Explain the Bellman equation and why it is important.
**Answer:**
The Bellman equation decomposes the value of a state into immediate reward plus expected discounted future value:
\[V^\pi(s) = R(s) + \gamma \sum_{s'} T(s, \pi(s), s') V^\pi(s')\]
It is important because it provides a recursive structure that connects state values, enabling iterative algorithms (value iteration, policy iteration) for planning and forming the basis for RL update rules (TD, Q-learning). The Bellman equation expresses the fundamental principle: value now = reward now + discounted future value.[1]

***

### Q4: What is the difference between planning and reinforcement learning?
**Answer:**
**Planning** (e.g., value iteration, policy iteration) assumes the agent knows the environment model \(T\) and reward \(R\), using them to compute optimal policies offline or via simulation.
**Reinforcement learning** is used when \(T\) and/or \(R\) are unknown and must be learned from interaction with the environment through trial and error. RL replaces model-based calculation with experience-based updates.[1]

***

### Q5: What is passive RL and what are the three main methods?
**Answer:**
Passive RL evaluates a **fixed policy** \(\pi\) by learning state utilities \(V^\pi(s)\) without changing the policy.

**Three methods:**
1. **Direct utility estimation:** Run trials, average observed reward-to-go per state; simple but ignores Bellman structure, slow.
2. **Adaptive Dynamic Programming (ADP):** Learn transition model from experience, solve Bellman equations (linear system) for \(V^\pi\); uses dependencies, faster, but requires storing model.
3. **Temporal Difference (TD) learning:** Model-free, updates \(V(s)\) using observed \(s'\) via bootstrapping; online, efficient, no model needed.[1]

***

### Q6: How does ADP differ from TD learning?
**Answer:**
**ADP** learns an explicit transition model \(P(s'|s)\) from observed transitions, then uses that model to compute utilities by solving Bellman equations—adjusting the utility of state \(s\) using **all successor states** through the model.
**TD learning** is model-free and updates utilities directly from sampled transitions, adjusting \(V(s)\) using **one sampled successor** \(s'\) at a time via the rule \(V(s) \leftarrow V(s) + \alpha [R(s) + \gamma V(s') - V(s)]\). TD avoids building a model, making it more scalable and online.[1]

***

### Q7: What is active RL and why is it harder than passive RL?
**Answer:**
Active RL requires the agent to **choose actions while learning**—the policy is not fixed. It is harder because the agent must handle the **exploration vs exploitation trade-off**: purely exploiting current knowledge may lock into suboptimal behavior based on faulty early learning, while exploring requires sacrificing short-term reward to gather information. The agent must decide which actions improve the model/policy, not just evaluate a given policy.[1]

***

### Q8: Explain the exploration vs exploitation trade-off.
**Answer:**
**Exploitation:** Choosing actions that appear best under the current learned model or policy to maximize immediate expected reward.
**Exploration:** Choosing actions to gather new information and improve the model or policy, possibly accepting lower short-term reward.

The trade-off is fundamental in active RL because pure exploitation may miss better options the agent hasn't tried, while pure exploration wastes reward on uninformative actions. Strategies like ε-greedy balance both by occasionally exploring randomly.[1]

***

### Q9: What is Q-learning and how does it work?
**Answer:**
Q-learning is an active RL algorithm that learns action-values \(Q(s,a)\)—the utility of performing action \(a\) in state \(s\)—without a model. 

**Update rule:**
\[Q(s,a) \leftarrow Q(s,a) + \alpha [R(s) + \gamma \max_{a'} Q(s',a') - Q(s,a)]\]

It is **off-policy** because it updates toward the greedy action (\(\max_{a'} Q(s',a')\)) even if a different exploratory action was taken. The derived policy is \(\pi(s) = \arg\max_a Q(s,a)\). Q-learning converges to optimal \(Q^*\) under suitable conditions.[1]

***

### Q10: What is SARSA and how does it differ from Q-learning?
**Answer:**
SARSA (State-Action-Reward-State-Action) also learns \(Q(s,a)\) but is **on-policy**:

**Update rule:**
\[Q(s,a) \leftarrow Q(s,a) + \alpha [R(s) + \gamma Q(s',a') - Q(s,a)]\]

where \(a'\) is the action **actually chosen** in \(s'\) under the current behavior policy (including exploration).

**Key difference from Q-learning:**
- Q-learning updates toward the greedy action (off-policy), assuming optimal future behavior
- SARSA updates based on actual next action (on-policy), reflecting exploration risk

In risky environments with ε-greedy exploration, SARSA typically learns safer policies because it accounts for the possibility of random exploration actions near hazards.[1]

***

### Q11: Give an example where SARSA would learn a safer policy than Q-learning.
**Answer:**
**Example:** Cliff-walking task with ε-greedy exploration.

- **Q-learning:** Updates assume greedy (safe) actions in future, so learns path close to cliff edge for shorter route. But ε-exploration occasionally takes random action, causing falls.
- **SARSA:** Updates reflect actual policy including ε-exploration risk, so learns value of being near cliff is lower (because random actions cause falls). Learns to stay farther from cliff edge for safety during learning.

Result: Q-learning finds theoretically optimal path but fails often during learning; SARSA finds safer path that accounts for exploration randomness.[1]

***

### Q12: Why does passive policy evaluation form a linear system, but optimal policy search does not?
**Answer:**
In passive policy evaluation, the policy \(\pi\) is **fixed**, so the Bellman equation is:
\[V^\pi(s) = R(s) + \gamma \sum_{s'} T(s, \pi(s), s') V^\pi(s')\]
This is linear in \(V\)—no max operator—so it forms a system of linear equations solvable directly.

For optimal policy, the Bellman equation is:
\[V^*(s) = R(s) + \gamma \max_a \sum_{s'} T(s, a, s') V^*(s')\]
The **max operator** makes it nonlinear, requiring iterative methods (value iteration) or alternating optimization (policy iteration).[1]

***

### Q13: What does "model-free" mean in RL, and why is it important?
**Answer:**
"Model-free" means the RL algorithm does not build or use an explicit model of the environment's transition function \(T(s,a,s')\). Instead, it learns directly from experience samples (observed transitions).

**Importance:**
- Scalable: avoids storing/learning potentially huge transition models
- Online: can update immediately from each experience
- Robust: works when model is complex, unknown, or non-stationary

Examples: TD learning, Q-learning, SARSA are model-free. ADP is model-based because it learns \(T\).[1]

***

### Q14: Why is direct utility estimation slow compared to TD or ADP?
**Answer:**
Direct utility estimation treats each state independently, averaging observed reward-to-go samples without exploiting the Bellman equation's dependencies between states. It must visit each state many times to get accurate estimates and does not propagate information between related states.

TD and ADP use Bellman structure: learning about one state's value helps update connected states. TD bootstraps from successor estimates; ADP solves the system of Bellman equations. Both propagate information faster, reducing sample requirements.[1]

***

### Q15: What is the role of the learning rate α in TD learning and Q-learning?
**Answer:**
The learning rate \(\alpha\) (0 < \(\alpha\) ≤ 1) controls how much the agent adjusts its value estimate based on new experience.

- **High α:** Fast adaptation to new information, but sensitive to noise (high variance)
- **Low α:** Slow, stable learning, less sensitive to individual samples (low variance, potentially slow convergence)

Common practice: start with higher \(\alpha\) and decay over time to balance exploration speed and convergence stability. \(\alpha\) must satisfy certain conditions (e.g., \(\sum \alpha_t = \infty\), \(\sum \alpha_t^2 < \infty\)) for convergence guarantees.[1]

***

### Q16: What is the discount factor γ and why is it used?
**Answer:**
The discount factor \(\gamma\) (0 < \(\gamma\) ≤ 1) weights future rewards relative to immediate rewards in the value function:
\[V(s) = R(s) + \gamma V(s') + \gamma^2 V(s'') + \ldots\]

**Purposes:**
1. **Mathematical:** Ensures infinite-horizon sums converge (if \(\gamma < 1\))
2. **Modeling:** Reflects preference for immediate rewards (impatience, uncertainty about distant future)
3. **Control:** Lower \(\gamma\) = short-sighted policy; higher \(\gamma\) = far-sighted policy

Typical values: 0.9–0.99.[1]

### Q24: What is bootstrapping in RL and why is it useful?
**Answer:**
**Bootstrapping** means updating a value estimate using **other value estimates** rather than waiting for actual final returns.

**Example (TD learning):**
\[V(s) \leftarrow V(s) + \alpha [R(s) + \gamma V(s') - V(s)]\]
Uses current estimate \(V(s')\) as target, not waiting for full episode to finish.

**Why useful:**
- **Faster learning:** Updates happen online after each step, not after full episodes
- **Lower variance:** Immediate reward \(R(s)\) + estimate \(V(s')\) has lower variance than full noisy return
- **Propagates information:** Learning about one state's value immediately affects connected states

**Trade-off:** Introduces bias early (bootstrapping from imperfect estimates), but bias decreases as estimates improve.[1]

### Q25: When would you prefer value iteration over policy iteration, or vice versa?
**Answer:**
**Value iteration:**
- Repeatedly apply Bellman update to \(V(s)\) until convergence, then derive policy at end
- **Prefer when:** State space is large, or you only need policy at the end (don't need intermediate policies)
- Each iteration is computationally cheap (simple update)

**Policy iteration:**
- Alternate: (1) policy evaluation (solve linear system for \(V^\pi\)), (2) policy improvement (greedy update)
- **Prefer when:** State space is small, or policy converges in few iterations (policy iteration often converges in fewer iterations than value iteration, but each iteration is more expensive)
- Particularly good for small state spaces where solving linear system is feasible

**In practice:** Both converge to optimal policy; choice depends on computational trade-offs and whether intermediate policies are useful.[1]

### Q26: What assumptions does Q-learning make for convergence to Q*?
**Answer:**
Q-learning converges to optimal \(Q^*\) under the following conditions:

1. **Infinite exploration:** Every state-action pair \((s,a)\) is visited infinitely often (ensures all parts of state-action space are learned)
2. **Learning rate decay:** Learning rate \(\alpha_t\) satisfies \(\sum_t \alpha_t = \infty\) (ensures learning doesn't stop prematurely) and \(\sum_t \alpha_t^2 < \infty\) (ensures noise averages out)
3. **Bounded rewards:** Rewards are finite
4. **Tabular representation or function approximation guarantees:** In practice, function approximation can violate convergence

These are theoretical guarantees; in practice, careful exploration strategies and tuning are needed.[1]

### Q27: Why is partial observability a challenge for the MDP framework?
**Answer:**
The standard MDP framework assumes **full observability**—the agent knows its current state \(s\). With partial observability, the agent only receives observations \(o\) that don't uniquely determine \(s\).

**Challenges:**
- **Belief states:** Agent must maintain probability distribution over possible states (belief state) based on observation history
- **History-dependent:** Optimal action may depend on history, not just current observation, violating Markov property
- **Complexity:** Belief-space planning is computationally harder

**Solution:** Partially Observable MDPs (POMDPs) extend MDPs with observation model, but are significantly harder to solve. In practice, agents may use recurrent networks, memory, or heuristics to handle partial observability.[1]

### Q28: How does multi-agent RL differ from single-agent RL?
**Answer:**
**Multi-agent RL (MARL) challenges:**
1. **Non-stationarity:** Each agent's learning changes the environment from other agents' perspectives—transition function and reward become non-stationary
2. **Credit assignment:** Hard to determine which agent's actions caused observed reward (especially in cooperative tasks)
3. **Coordination:** Agents must learn to coordinate, which may require communication or emergent conventions
4. **Scalability:** State-action space grows exponentially with number of agents

**Approaches in MARL:**
- Independent learners (each agent learns separately, treating others as environment)
- Centralized training, decentralized execution
- Communication and coordination protocols
- Emergent cooperation/competition

Assignment 1 used independent RL per agent + subsumption for local coordination.[2]

### Q29: What is the difference between on-policy and off-policy learning?
**Answer:**
**On-policy learning:** Learns the value of the policy **being executed** (behavior policy = target policy)
- Example: **SARSA** updates \(Q(s,a)\) based on next action \(a'\) actually taken under current policy (including exploration)
- Learns value that reflects actual behavior, including exploration randomness

**Off-policy learning:** Learns the value of a **different policy** (target policy) from experience generated by another policy (behavior policy)
- Example: **Q-learning** updates toward greedy action (\(\max_{a'} Q(s',a')\)) even if exploratory action was taken
- Behavior policy can explore while target policy is greedy/optimal

**Advantage of off-policy:** Can learn optimal policy while behaving exploratively; can reuse experience from old policies.[1]

### Q30: If you had to re-do Assignment 1, what would you change to improve learning in crowded scenarios?
**Answer:**
**Possible improvements:**

1. **State representation:** Add features for nearby agents (relative positions, velocities) so policy learns to anticipate and avoid crowding
2. **Reward shaping:** Add reward for maintaining safe separation, not just penalizing collisions—encourages proactive spacing
3. **Coordinated exploration:** Use communication or shared learning to reduce redundant exploration and interference
4. **Hierarchical RL:** Learn separate sub-policies for "navigation to circle" and "following circle," switching based on context
5. **Subsumption tuning:** Adjust obstacle avoidance threshold or priority to allow more circle-following learning while maintaining safety
6. **Curriculum learning:** Start with few agents, gradually increase density as policies improve
7. **Multi-agent credit assignment:** Explicitly model other agents and learn joint Q-values or use centralized training with decentralized execution

These address the core issue in Test 2: agents couldn't learn task because obstacle avoidance dominated.[2]
