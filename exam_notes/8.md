## CORE DEFINITIONS


### What is “Multi-Agent Deep Learning (MADL)” in this course context?
MADL is the use of deep neural networks to learn representations and decision-making policies for multi-agent systems, especially when state/action spaces are too large or continuous for tabular methods.[1][2][3]
In the course framing, MADL also includes federated learning as a way for many agents/clients to collaboratively train a model without sharing raw local data.[4]


### Why do we need deep learning in RL?
Tabular RL stores values explicitly (e.g., \(Q(s,a)\)), so it becomes infeasible when \(s\) is high-dimensional (images, lidar, continuous poses) or continuous.[3][1]
Deep RL replaces the table with a neural network approximator (e.g., a Deep Q-Network), enabling generalization across similar states.[3]


### What is a Deep Q-Network (DQN)?
A DQN is a neural network that approximates the action-value function \(Q(s,a;\theta)\) and is trained from experience to maximize long-term reward.[3]
The original DQN approach introduced stabilizing mechanisms including experience replay and a (periodically updated) target network.[3]


### What is a Graph Neural Network (GNN) (as used in MAS)?
A GNN is a neural network designed for graph-structured data where nodes and edges represent entities and relations (e.g., agents and communication links).[5]
Message-passing GNNs iteratively aggregate information from neighbors to compute node embeddings that capture local relational context.[6][5]


### What is “message passing” in GNNs?
Message passing is the repeated process where each node (agent) computes “messages” from neighbors and aggregates them to update its own representation.[6][5]
Stacking multiple message-passing rounds increases the receptive field from 1-hop neighbors to multi-hop neighborhoods.[6]


### What is Federated Learning (FL)?
Federated learning trains a shared/global model using decentralized local data by sending model updates (not raw data) to an aggregator that combines them.[4]
It is designed for settings with statistical heterogeneity (non-IID data) and systems heterogeneity (clients performing different amounts of work).[4]

## WHY DEEP RL SHOWS UP IN MAS


### The scaling problem
Many MAS tasks have large or continuous state spaces, so classic tabular Q-learning and dynamic programming methods discussed earlier in the course do not scale well.[1][3]
Deep RL addresses this by learning a function approximator that generalizes, rather than storing values for every state-action pair.[3]


### The “MARL headache”: non-stationarity
In multi-agent learning, each agent’s environment changes as other agents update their policies, which can break single-agent RL assumptions.[6]
This is one motivation for architectures that separate training-time information access from execution-time constraints (e.g., CTDE).[6]

## DQN: WHAT EXAMINERS OFTEN ASK


### Key DQN mechanisms (must be able to explain)
**Experience replay:** DQN stores transitions and samples mini-batches from a replay memory to reduce correlation between consecutive samples and stabilize learning.[7][3]
**Target network:** DQN uses a separate target network whose parameters are updated less frequently, reducing instability from rapidly moving targets.[7][3]


### What to say in 30 seconds (DQN pitch)
DQN replaces a Q-table with a neural network and uses experience replay plus a target network to stabilize training.[7][3]
This enables RL from high-dimensional observations such as pixels and other large sensory inputs.[3]


***


## GNNs FOR MULTI-AGENT SETTINGS


### Why graphs are natural in MAS
In decentralized/distributed multi-agent systems, communication/sensing constraints can be encoded as a graph where nodes are agents and edges represent possible interaction links.[5]
GNNs are commonly used in this regime to produce per-agent representations that respect the system’s relational structure.[5]


### Why message passing helps
Message passing provides permutation-invariant aggregation over a variable number of neighbors, which matches MAS settings where neighbor sets change over time.[5][6]
This supports decentralized execution because each agent can compute its embedding from locally available neighbor information.[5]


### “GNN + RL” idea (decentralized execution)
A common pattern is to encode local observations + neighbor context via a message-passing GNN and feed the resulting embedding into a policy/value network for action selection.[6][5]
This is aligned with learning scalable decentralized policies under communication constraints.[5]

## FEDERATED LEARNING IN MAS


### Canonical FL loop (server-based)
1. Each client/agent trains locally on its own data.[4]
2. Clients send model updates to a coordinator/aggregator (often called a server).[4]
3. The server aggregates updates into a new global model and distributes it back.[4]


### FedAvg vs FedProx vs FedNova (exam-ready)
**FedAvg:** the standard baseline that aggregates client updates by averaging (commonly weighted by local data size).[4]
**FedProx:** a generalization of FedAvg that adds a proximal term to improve robustness under statistical and systems heterogeneity.[4]
**FedNova:** a normalized averaging method designed to reduce objective inconsistency and handle heterogeneous amounts of local work.[8][9]


### Why non-IID (statistical heterogeneity) is hard
Federated optimization explicitly targets learning when client data comes from non-identical distributions, which can slow or destabilize convergence compared to IID assumptions.[4]
Benchmarks and practical FL work emphasize that “Non-IID” data is a primary difficulty driver for FL methods.[10]


### MAS-flavored variants: PSFL (if it was in your lecture)
Proximity-based Self-Federated Learning (PSFL) forms local “federations” so that nearby/similar agents share models more locally rather than always training one global model.[11][12]
The key MAS connection is that federation formation becomes a coordination/self-organization problem (who trains with whom).[11]

## COMPLETE EXAM QUESTIONS & ANSWERS (TOPIC 8)


### Q1: Why do we need Deep Q-learning instead of tabular Q-learning?
**Answer:** Tabular Q-learning requires storing/estimating \(Q(s,a)\) for every state-action pair, which is infeasible for high-dimensional or continuous state spaces.[1][3]
Deep Q-learning replaces the Q-table with a neural network approximator, enabling generalization across states.[3]


***


### Q2: What is the main idea behind DQN?
**Answer:** DQN approximates the action-value function with a deep neural network and learns its parameters from experience to maximize long-term reward.[3]
It became practical by introducing stabilizing techniques such as experience replay and a target network.[3]


***


### Q3: What problem does experience replay solve in DQN?
**Answer:** Experience replay reduces correlations between consecutive samples by training on randomly sampled past transitions rather than only the latest transition stream.[7][3]
This makes gradient updates more stable and data-efficient compared with purely on-trajectory updates.[3]


***


### Q4: Why does DQN use a target network?
**Answer:** The target network is updated less frequently than the online network, which reduces instability from a rapidly changing bootstrapped target.[7][3]
This helps prevent divergence when learning Q-values with function approximation and bootstrapping.[3]


***


### Q5: What makes MARL harder than single-agent RL?
**Answer:** From one agent’s perspective, the environment becomes non-stationary because other agents’ policies change during learning.[6]
This breaks the standard RL assumption of fixed transition dynamics and can destabilize learning.[6]


***


### Q6: What is CTDE (centralized training, decentralized execution) and why is it used?
**Answer:** CTDE trains with extra/global information (e.g., joint state or joint actions) but deploys policies that act only on local observations at runtime.[6]
It is used to improve training stability while respecting decentralized execution constraints typical in MAS.[6]


***


### Q7: Why are GNNs a good fit for MAS?
**Answer:** MAS interactions can be represented as graphs where nodes are agents and edges represent communication/sensing links.[5]
GNNs exploit this structure by computing per-agent representations via neighbor aggregation.[5][6]


***


### Q8: Define message passing in a GNN in one or two sentences.
**Answer:** Message passing iteratively aggregates information from each node’s neighbors to update the node’s embedding.[5][6]
With more message-passing rounds, information can propagate to multi-hop neighborhoods.[6]


***


### Q9: What does “decentralized execution” mean in the GNN+RL setting?
**Answer:** Each agent selects actions locally using its own observation and information received from nearby neighbors defined by the interaction graph.[5]
No centralized controller is required at inference time, assuming the local communication constraints are satisfied.[5]


***


### Q10: What is federated learning (FL)?
**Answer:** FL trains a shared model by keeping raw data on local clients and sharing model updates for aggregation.[4]
It is designed for decentralized data and can handle heterogeneity across clients in data distributions and compute resources.[4]


***


### Q11: What is “non-IID” data in FL, and why does it matter?
**Answer:** Non-IID means different clients have data from different distributions, which is a central challenge in federated optimization.[10][4]
It can cause client drift and unstable convergence if aggregation assumes clients represent the same underlying distribution.[4]


***


### Q12: FedAvg vs FedProx vs FedNova (short comparison)
**Answer:** FedAvg aggregates client updates via averaging and is a baseline for federated optimization.[4]
FedProx modifies local objectives with a proximal term to improve robustness under heterogeneity.[4]
FedNova normalizes aggregation to reduce objective inconsistency when clients do unequal amounts of local work.[9][8]


***


### Q13: When would you prefer FedProx over FedAvg?
**Answer:** FedProx is motivated for heterogeneous settings where clients may do variable local work and have non-identical data distributions.[4]
Its proximal term aims to reduce client drift relative to the global model during local updates.[4]


***


### Q14: What is the intuition behind FedNova?
**Answer:** FedNova aims to correct for differences in the amount of local computation across clients by normalizing updates before aggregation.[8][9]
This addresses objective inconsistency that can arise when clients contribute updates computed under different effective step counts.[9]


***


### Q15: What is PSFL (Proximity-based Self-Federated Learning) in one sentence, and why is it “MAS-flavored”?
**Answer:** PSFL forms local federations so that nearby/similar agents share models more locally rather than relying only on one global model.[12][11]
It is MAS-flavored because “who trains with whom” becomes a decentralized coordination/self-organization problem.[11]


***


### Q16: How do GNNs relate to communication constraints in MAS?
**Answer:** In distributed/decentralized settings, the communication topology can be represented as a graph, and message passing can be restricted to edges that correspond to allowed communication links.[5]
This makes the learned representation respect what information is actually available to each agent.[5]


***


### Q17: Give an example architecture sketch for “GNN + DQN-like learning.”
**Answer:** Encode each agent’s local observation as a node feature, aggregate neighbor features with a message-passing GNN to get an embedding, then feed that embedding into a Q-network or policy head for action selection.[6][5]
This supports learning a decentralized policy that still conditions on neighborhood context.[5]


***


### Q18: What is the link between this topic and earlier RL material in the course?
**Answer:** Earlier RL material defines MDPs, policies, value functions, and Q-learning in a tabular setting.[1]
DQN keeps the same goal (learning an action-value function) but replaces the table with a deep function approximator and adds stabilizers like replay/target networks.[1][3]
