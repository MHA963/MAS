## CORE DEFINITIONS

### What is an agent architecture?
An agent architecture is the internal organization of an agent: how it maps perceptions (and possibly memory/models/goals) into actions over time.[1]
In this course topic, architectures are commonly categorized by how much *internal state* they maintain and how explicitly they reason about the future.[1]

### The “5 core” agent types (taxonomy)
The lecture’s core paradigms are: reflex agents, model-based agents, goal-based agents, utility-based agents, and learning agents.[1]
They mainly differ in whether they keep internal state, whether they evaluate future consequences (planning/search), and whether they adapt from experience.[1]

### What is an MDP?
A Markov Decision Process (MDP) models sequential decision-making in a **fully observable**, stochastic environment with additive reward, and is defined by the tuple \(\langle S, A, T, R\rangle\).[1]
Here \(T(s,a,s') = P(s'|s,a)\) is the stochastic transition function and \(R(s)\) is the reward function as presented in the slides. [1]

### Policy and value (why they matter)
A policy \(\pi: S \to A\) specifies what action the agent should take in any state.[1]
The value function \(V^\pi(s)\) is the expected total payoff (discounted cumulative reward) when starting in \(s\) and following \(\pi\).[1]

### Bellman equations (exam core)
The Bellman expectation equation (policy evaluation form) is: \(V^\pi(s)=R(s)+\gamma\sum_{s'}P(s'|s,\pi(s))V^\pi(s')\). [1]  
The optimal value function \(V^*(s)\) is defined by replacing “follow \(\pi\)” with a max over actions, and the optimal policy \(\pi^*\) can be derived using argmax.[1]

### Why reinforcement learning (RL)?
Classic planning with value/policy iteration assumes the agent knows the environment model \(T\) and the reward function \(R\), which is often unrealistic.[1]
Reinforcement learning is introduced as the approach for learning good behavior (or good value estimates) from interaction when that model knowledge is missing or incomplete.[1]

## ARCHITECTURE TYPES (WITH EXAM HOOKS)

### Reflex agents
Reflex agents select actions using simple condition–action rules based directly on the current percept.[1]
They have no internal state, which makes them fast but brittle when the environment is partially observable or noisy.[1]

### Model-based agents
Model-based agents maintain an internal state (“model”) that summarizes relevant history and how the world evolves.[1]
This internal state enables functioning under partial observability, because decisions can depend on more than just the current percept.[1]

### Goal-based agents
Goal-based agents represent desired goal states and choose actions based on whether they help reach a goal.[1]
They often require search/planning over sequences of actions, which improves flexibility but costs computation time.[1]

### Utility-based agents
Utility-based agents use a utility function to rank outcomes, not just classify them as goal/not-goal.[1]
This supports trade-offs (e.g., speed vs safety) and naturally connects to stochastic decision-making via expected utility/value.[1]

### Learning agents
Learning agents improve performance over time by updating internal components based on experience (e.g., models, value estimates, or policies).[1]
In the lecture, reinforcement learning is a central mechanism used to realize learning agents.[1]

### Quick comparison table (good for oral exam)
| Architecture | What it uses | Strength | Weakness / when it fails |
|---|---|---|---|
| Reflex | Current percept → rules. [1] | Very fast/simple. [1] | No memory; brittle under partial observability. [1] |
| Model-based | Percept + internal state/model. [1] | Handles partial observability/dynamics better. [1] | Needs state update design; more complexity. [1] |
| Goal-based | Goals + planning/search. [1] | Flexible long-horizon behavior. [1] | Planning can be expensive. [1] |
| Utility-based | Utility/value comparisons. [1] | Trade-offs and “best” among many options. [1] | Needs a well-defined utility/reward. [1] |
| Learning | Learns from experience (RL). [1] | Adapts when model/rules are unknown. [1] | Needs data/exploration; can be unstable. [1] |

## PLANNING IN MDPS (VALUE/POLICY ITERATION)

### Value iteration
Value iteration repeatedly applies Bellman optimality backups to converge toward \(V^*\), and then derives \(\pi^*\) via argmax.[1]
This is typically presented as a dynamic programming method when \(T\) and \(R\) are known.[1]

### Policy iteration
Policy iteration alternates between (1) policy evaluation (solve for \(V^\pi\)) and (2) policy improvement (update \(\pi\) using argmax).[1]
The slides emphasize it as good for relatively small state spaces because policy evaluation can be handled as a system of linear equations.[1]

### Key “oral exam” angle
Be ready to explain the difference between evaluating a fixed \(\pi\) (Bellman expectation, no max) and computing optimal behavior (Bellman optimality, has max/argmax).[1]
Also be ready to state the “big assumption” behind dynamic programming planning: the model \(T\) and rewards \(R\) are known.[1]

## RL + SELF-ADAPTIVE ARCHITECTURES

### Passive RL vs active RL
In passive RL, the policy \(\pi\) is fixed and the agent’s task is to learn how good it is (estimate utilities/values).[1]
In active RL, the agent must also choose actions, which creates the exploitation–exploration trade-off described in the slides.[1]

### Passive RL methods in the slides
Direct utility estimation runs many trials and uses returns (“reward-to-go”) as samples, maintaining running averages that converge to true values.[1]
Adaptive Dynamic Programming (ADP) speeds value estimation by incrementally learning a transition model from observed transitions and then using Bellman equations without a max operator (linear).[1]
Temporal Difference (TD) is model-free and updates values from single observed transitions using a learning rate \(\alpha\): \(V^\pi(s)\leftarrow V^\pi(s)+\alpha(R+\gamma V^\pi(s')-V^\pi(s))\).[1]

### Active RL: Q-learning (+ SARSA mention)
Q-learning learns action-values \(Q(s,a)\) and updates using a max over next-state actions, which makes it an active RL method in the lecture framing.[1]
SARSA is introduced as a variant (commonly explained as on-policy compared to Q-learning’s off-policy max update).[1]

### MAPE-K architecture (for “compare” questions)
MAPE-K is a control-loop architecture structured around Monitor, Analyze, Plan, Execute, and a shared Knowledge base.[2][3]
In common descriptions, Monitor gathers data via probes/sensors, Analyze determines whether adaptation is needed, Plan selects an adaptation procedure, Execute enacts it through effectors, and Knowledge stores shared runtime information.[3]

### Self-aware architecture (high-level, exam-safe)
In a self-aware architectural style, systems are often described using self-awareness processes (learning/acquiring knowledge about “self” and context) and self-expression processes (selecting/performing actions based on that knowledge), typically with sensors and actuators in the loop.[4]
This style emphasizes online learning/knowledge acquisition and behavior determination informed by that learned knowledge, and may include meta-self-awareness for runtime adaptation of the adaptation itself.[4]

## COMPLETE EXAM QUESTIONS & ANSWERS (+ CHECKLIST)

### Q1: What are the main paradigms for building agent architectures?
**Answer:** The core paradigms presented are reflex, model-based, goal-based, utility-based, and learning agents.[1]
They differ by whether they maintain internal state, reason about future consequences, optimize utilities/value, and/or adapt through experience.[1]

***

### Q2: Compare reflex and model-based agents. When is each suitable?
**Answer:** Reflex agents use direct condition–action rules based on percepts and do not maintain internal state, which makes them simple and fast.[1]
Model-based agents keep an internal state/model, which is useful under partial observability and dynamic environments because decisions can depend on history.[1]

***

### Q3: Compare goal-based and utility-based agents.
**Answer:** Goal-based agents select actions to reach any state satisfying the goal condition and often rely on planning/search to find action sequences.[1]
Utility-based agents rank outcomes using a utility function, enabling trade-offs among alternatives and aligning naturally with value-based decision-making.[1]

***

### Q4: Define an MDP and explain what a policy is.
**Answer:** An MDP is defined by \(\langle S,A,T,R\rangle\) with stochastic transitions \(T(s,a,s')=P(s'|s,a)\) and reward function \(R(s)\) in a fully observable stochastic setting. [1]  
A policy \(\pi:S\to A\) maps each state to an action choice.[1]

***

### Q5: State the Bellman equation and interpret \(\gamma\).
**Answer:** The Bellman expectation equation for a fixed policy is \(V^\pi(s)=R(s)+\gamma\sum_{s'}P(s'|s,\pi(s))V^\pi(s')\). [1]  
\(\gamma\) is the discount factor weighting future rewards relative to immediate rewards in the lecture formulation.[1]

***

### Q6: Value iteration vs policy iteration (how do they differ?)
**Answer:** Value iteration repeatedly applies Bellman optimality backups to approximate \(V^*\) and derives \(\pi^*\) at the end using argmax.[1]
Policy iteration alternates between evaluating the current policy (solve for \(V^\pi\)) and improving it via argmax, and is highlighted as good for small state spaces.[1]

***

### Q7: What is the “big assumption” behind planning methods, and how does RL address it?
**Answer:** Planning with dynamic programming assumes the agent knows the transition model \(T\) and reward function \(R\).[1]
Reinforcement learning targets learning good value estimates/policies from observed experience when \(T\) and/or \(R\) are not given explicitly.[1]

***

### Q8: Passive RL vs active RL—what’s the difference?
**Answer:** Passive RL evaluates a fixed policy \(\pi\) (learn “how good is this policy?”), while active RL must also decide which actions to take.[1]
Active RL introduces the exploitation–exploration trade-off because greedy choices can prevent learning a correct model/value estimate.[1]

***

### Q9: Compare ADP and TD learning (both passive in the slides).
**Answer:** ADP is model-based in the sense that it incrementally builds a transition model from observed transitions and then uses Bellman equations (linear, no max) to compute values for the fixed policy.[1]
TD is model-free and updates value estimates directly from observed transitions using a learning rate, without an explicit transition model.[1]

***

### Q10: What is Q-learning and what does it learn?
**Answer:** Q-learning is presented as an active RL method that learns action-values \(Q(s,a)\), i.e., the utility of taking action \(a\) in state \(s\).[1]
Its update uses a max over next actions, and SARSA is mentioned as a variant in the slides.[1]

***

### Q11: Compare MAPE-K and self-aware architectures (high-level).
**Answer:** MAPE-K is an adaptation control loop with explicit phases Monitor–Analyze–Plan–Execute operating over a shared Knowledge base.[3]
Self-aware architectural styles emphasize learned knowledge about the system and context (self-awareness) coupled with action selection/execution (self-expression), sometimes including meta-self-awareness for adapting the adaptation mechanism.[4]
